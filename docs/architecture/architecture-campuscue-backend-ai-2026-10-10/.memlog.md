- (decision) Paradigm: two hexagons (ports-and-adapters) joined by typed HTTP contracts. Core = functional-core/imperative-shell modular monolith (api -> application -> domain; infrastructure implements ports). Agent = bounded tool-calling orchestrator with LLM provider as a port. Binds all units. Prevents: domain logic leaking into routes/LLM, I/O in scheduling code, two layering styles.
- (decision) Layering enforced mechanically with import-linter contracts in both services (domain imports nothing from fastapi/sqlalchemy/httpx; api never imports infrastructure; student_private package importable only by student routes/services). Prevents silent erosion under parallel feature work.
- (decision) Core is synchronous (def routes, sync SQLAlchemy 2.x + psycopg3); Agent is async (httpx.AsyncClient, async Groq). Prevents mixed sync/async session bugs across feature slices. Rejected: async SQLAlchemy in Core (extra failure modes, no load need).
- (decision) Single schedule write path: every create/reschedule/confirm/override/cancel of an event goes through ScheduleWriteService, which in ONE transaction takes pg_advisory_xact_lock(campus-schedule key), re-runs the pure conflict engine on committed rows, applies overrides, writes event+revision+audit, commits. Routes/repos cannot write events otherwise (import-linter). Rejected: SERIALIZABLE+retry (retry storms, harder to reason), padded-range GiST exclusion for gap (cannot express pair-scoped overrides or stage-dependent applicability). Same-venue GiST exclusion on CONFIRMED rows deferred as optional backstop. Concurrency test required before claiming enforcement.
- (decision) Conflict model: constraints VENUE_OVERLAP and CAMPUS_GAP evaluated independently per candidate/other pair; one conflict emitted per violated constraint (never short-circuited), so a CAMPUS_GAP override removes only its own conflict. Severity is a pure function of stage: blocking only when the candidate is being CONFIRMED against another CONFIRMED event; any pair where either side is non-CONFIRMED yields TENTATIVE_OVERLAP at warning severity with an additive field naming the violated constraint(s). UNKNOWN_AVAILABILITY emitted whenever no authoritative availability source exists. DEPENDENCY_CONFLICT for shared resource/audience/organizer.

- (assumption) Override scope: a CAMPUS_GAP or VENUE_OVERLAP override is recorded per named event pair (event_ids) and waives only that pair for that constraint; it does not exempt either event from other events. Admin-only, derived server-side.
- (decision) Lifecycle: event and commitment state machines are explicit transition tables in domain/lifecycle; no endpoint accepts a status field. CONFIRMED (event or commitment) is reachable only via confirm use cases requiring an authorized actor plus an evidence record; reported_by and verified_by are distinct columns; organizer claims stay REPORTED until verified. A change proposal moves affected commitments to NEEDS_REVALIDATION, never deletes evidence. Event lifecycle DRAFT PROPOSED SUBMITTED CONFIRMED COMPLETED plus REJECTED CANCELLED; commitment lifecycle DRAFT REQUESTED ACKNOWLEDGED CONDITIONALLY_CONFIRMED CONFIRMED NEEDS_REVALIDATION CLOSED. Closure is tracked separately from event COMPLETED.
- (decision) Unit of work: every mutation = one transaction that writes state change + event_revisions row (when event fields change) + audit_events row, via a single commit_mutation helper; handlers never call session.commit. Optimistic concurrency via expected_revision (stale => 409 STALE_REVISION). Idempotency-Key stored with actor + request hash + response; same key different body => 422.
- (decision) Agent write surface is exactly one thing: it may only file AgentAction proposals (status PROPOSED, requires_human_review true) into a Core-owned table. Core dry-runs the target operation (schema validation + conflict check) at proposal time and re-validates inside the transaction when the human confirms via the web (POST agent-actions/{id}/confirm) under the HUMAN's identity. The Agent can therefore only ever say proposed, never done. Binds record_commitment, request_event_change, create_event_draft, create_followup_draft. Prevents: agent mutating domain tables, false success claims, double execution (confirm is idempotent by action_id).
- (decision) Identity delegation: Core mints a short-lived (<=120s) HS256 delegation JWT per chat turn (iss core, aud agent-tools, sub user id, jti, req request id, scope organizer). Agent treats it as opaque and forwards it on tool calls; only Core verifies it and re-derives roles/club memberships from the DB for sub (token role claims are never trusted). Tokens are never minted for STUDENT actors. Agent holds no signing secret.
- (decision) Tool facade: Agent calls Core only through /internal/v1/agent-tools/* (read-shaped, size-bounded, LLM-safe responses) plus the AgentAction proposal endpoint; both call the same application services as public routes (no duplicated logic) and are authorized as the delegated user. - (decision) Agent orchestration: no agent framework (pydantic-ai 2.55.0 exists; rejected because bounds, trace, untrusted-data wrapping and FakeProvider seam must be ours); hand-rolled loop over a Provider port (GroqProvider, FakeProvider). Tool = name + input model + output model + effect READ|PROPOSE + timeout + max_output_bytes. Hard bounds per turn: max tool calls (default 6), wall deadline (default 20s), per-tool timeout, output byte cap, one retry on malformed model output. Every tool call arg validated with Pydantic before dispatch.
- (decision) Untrusted data + grounding: tool results and RAG excerpts enter the model context only inside delimited untrusted-data blocks, never in system role.
